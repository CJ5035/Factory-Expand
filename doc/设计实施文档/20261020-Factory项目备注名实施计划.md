## 一、目标与功能边界

在 Factory Desktop 0.202.0 左侧会话列表的项目分组菜单中增加“编辑备注”。有备注时，项目标题显示备注；无备注时显示原名；悬停保留原始名称和可取得的路径。编辑支持保存、取消及留空清除，保存成功立即刷新，重启后保留。

本轮范围：

- 普通项目及 Worktree 项目分组均可设置备注；按 Factory 原生项目分组标识区分本地与远端项目。
- `Z3.Unknown` 的 `ungrouped` 是“无项目”会话集合，不提供备注；按电脑、按时间及未分组视图不增加备注入口。
- 复用原生菜单、React 组件和对话框样式；备注限制 80 个字符，首尾空白去除，换行和制表符转为空格。
- 独立存储备注，避免 Factory 设置 schema 过滤未知字段；重新应用扩展及恢复原始程序不删除备注文件。
- 多窗口显示同一份备注；两个窗口编辑不同项目时不互相覆盖。
- 新增界面文案跟随现有中英文语言状态，备注本身作为用户内容原样显示。

本轮不包含：其他页面的项目标题统一替换、网页端/手机端同步、ZCode 数据导入、云端账户同步、任务状态点及旧版 0.200.0/0.201.0 新功能适配。项目备注不修改目录、仓库名、分支、会话标题或 Factory 原生 Worktree 重命名操作。

## 三、数据及接口约定

### 1. 存储

由主进程使用以下真实路径表达式读写文件：

```js
Z.join(i.getDesktopHomeDir(), i.getFactoryDirName(), 'factory-expand.json')
```

`getDesktopHomeDir` 导出对应 `RY()`，返回 `FACTORY_HOME_OVERRIDE` 或系统 home；**它自身不是 Factory 配置目录**。`getFactoryDirName` 导出对应 `Co()`，返回当前运行配置的 Factory 目录名。常规路径为 `C:/Users/11013/.factory/factory-expand.json`，实际值以运行配置为准，不能在模块中硬编码 `.factory`。测试直接向存储模块注入临时绝对 `filePath`，不得更改本机 `FACTORY_HOME_OVERRIDE` 或登录配置。

```json
{
  "version": 1,
  "projectRemarks": {
    "<Factory 原生项目分组键>": "生产环境"
  }
}
```

- `version: number`：固定为 1；未知版本报错，不覆盖原文件。
- `projectRemarks: Record<string, string>`：键来自有效项目分组的 `Eo.key`，值为清理后的备注。清除时删除单个键。UI 仅在 `fa && fa.kind !== Z3.Unknown` 时提供此键；该处 `fa` 已由原始代码限制为项目分组。
- 不自行将远端路径转小写，不使用目录短名、不重建 Factory 分组身份。项目路径或原生分组身份改变后，按新项目处理。
- 读文件不存在时返回空映射；JSON 损坏、结构非法或读取失败时保留文件并报告错误，不能当空映射覆盖。
- 使用安全的自有属性读取/映射构造，防止特殊键与对象原型混淆。
- 写入串行处理：每次只提交一个项目的变更，合并主进程最新映射，经同目录唯一临时文件和原子替换落盘；替换成功后更新内存并广播。失败保留旧数据及编辑内容。
- 长度按 JavaScript/原生 input 的 UTF-16 code unit 计算，清理后不得大于 80；不静默截断，主进程和 UI 使用相同规则。持久化结构中的空备注、非字符串值和超长值视为非法数据。
- 存储成功读取后使用主进程缓存；不支持运行中手工修改 JSON 的热加载。首次读取失败不缓存为成功，点击重试重新读取；主进程重启后从文件重新加载。
- 同项目并发编辑采用主进程队列中最后成功写入的值；不同项目合并保留。失败的队列任务不能使后续任务永久失败。
- 每次 API 返回独立可序列化快照；广播给已销毁窗口失败只记日志，不把已成功落盘的保存报为失败。临时文件写入失败应关闭句柄并清理临时文件，不删除原文件。
- 原子替换逻辑参考既有 `scripts/lib/env.mjs::atomicJson`；运行时模块不依赖仓库安装脚本。

### 2. 主进程与 preload

拟增加以下限定接口，所有返回值均为可序列化对象：

```text
electronAPI.projectRemarks.get()
  -> Promise<{ revision: number, projectRemarks: Record<string,string> }>

electronAPI.projectRemarks.set({ key: string, remark: string })
  -> Promise<{ revision: number, projectRemarks: Record<string,string> }>

electronAPI.projectRemarks.onChanged(listener)
  -> unsubscribe: () => void
```

对应 IPC 为 `factory-expand:projectRemarks:get`、`factory-expand:projectRemarks:set` 及 `factory-expand:projectRemarks:changed`。`set` 在主进程校验字符串类型、非空键及 80 字符上限，不接收文件路径或整份映射。文件路径仅由主进程决定。

`revision` 为主进程本次运行内递增序号，初始值 0，成功写入变更后递增；相同值重复保存不改文件和 revision。低于当前 revision 的读取/保存应答被忽略，相同 revision 复用现有快照。订阅先于初始读取建立；同一 renderer 共享客户端。最后一个订阅者卸载时移除 preload 监听，重新挂载时重新订阅并 get；连接代号隔离旧连接的迟到应答。

renderer 客户端状态固定为 `{ status, revision, projectRemarks, error }`：`status` 为 `idle | loading | ready | error`，未加载 revision 为 -1。`getSnapshot()` 在没有变化时返回同一对象，满足 `useSyncExternalStore` 的引用稳定要求。失败时项目继续显示原名或最近成功备注，编辑框显示加载错误与“重试”，尚未成功加载时禁止保存，防止覆盖不可读取的数据。

注册器 `registerProjectRemarks({ ipcMain, BrowserWindow, filePath })` 对同一 `ipcMain` 重复调用返回同一服务，不重复 handle。文件 I/O 延迟到 get/set，损坏备注文件不得导致 Factory 启动失败。IPC 异常使用可传递的 Error message，UI 显示本地化通用错误，不依赖 Electron 不保证保留的自定义 `Error.code`。preload 的 `onChanged` 只把 payload 交给 listener，返回移除该次 listener 的函数，不转交 Electron event。

### 3. 项目显示与编辑

在原生 `ukt` 外增加小型 React 包装组件，接收原始 props 和项目分组键：

```text
ProjectRemarkGroup({ factoryProjectKey, ...originalGroupProps })
  -> 原生项目分组 + 原生备注编辑框
```

包装组件自身用 Factory 的 `P.useSyncExternalStore` 订阅备注快照，并调用由 Factory `ce("components")` 提供的语言 Hook。按快照生成新 `label`、`tooltip` 和菜单项，再把其他 props 原样传给 `ukt`。这样保存后可更新显示，而不依赖父组件中 React 编译缓存恰好失效。不另行导入 React/Preact。无有效项目键时直接使用原生 `ukt`，不能条件式调用同一个组件中的 Hook。

有效备注的 tooltip 使用 `[原始 label, 原始 tooltip].filter(Boolean)` 去重后以换行连接；没有备注时保留原始 tooltip。菜单数组只在尾部追加 `{ key:'factory-expand-edit-remark', icon:'edit-3', label, onSelect }`，不修改原数组。所有排序、React key、分组身份、拖动和会话回调均沿用原始 props。

对话框显示原始项目名及可取得的路径，输入预填当前备注。若初次读取尚未结束，输入和保存均禁用；首次加载成功时预填一次，之后其他窗口的更新不覆盖已编辑草稿。保存成功关闭；取消不写入；失败显示错误并保留输入，可重试。保存中防止重复提交；中文输入法组合输入时不因 Enter 提前保存。复用原生 Modal 的焦点约束与键盘退出行为。

保存中的取消按钮和关闭操作暂禁用，避免把已经提交的写入误认为取消；未提交时 Escape/取消不发 set。其他窗口更新同一项目时刷新标题，但不覆盖当前正在编辑的输入。对话框退出或分组卸载后，未完成操作的应答不得触发已卸载组件更新。

## 附录 B：运行时接口与实现边界

| 入口/内部职责 | 参数与结果 | 必须行为 |
|---|---|---|
| CJS `createRemarksStore` | `{filePath:string,fs?:typeof import('node:fs/promises')}` → `{get,set}` | 生产默认 fs/promises；测试可覆盖 rename 制造确定性失败 |
| store.get | `()` → `Promise<{revision:number,projectRemarks:Record<string,string>}>` | 串行读取/等待在先写入，返回克隆；失败可重试 |
| store.set | `({key:string,remark:string})` → 同 get | 参数校验、规范化、按键合并；成功后更新 revision，无变更不写 |
| store 内部 load | `()` → `Promise<void>` | ENOENT 得空 map；其他 I/O/格式错误抛错且不把 initialized 标为成功 |
| store 内部 persist | `({version:1,projectRemarks})` → `Promise<void>` | 唯一 temp、wx、write/sync/close/rename；失败清理 temp；先于内存更新 |
| store 内部 snapshot | `()` → 快照 | 独立对象与 map，自有键安全；不向外泄漏内部可变 map |
| CJS `registerProjectRemarks` | `{ipcMain,BrowserWindow,filePath}` → `{store}` | WeakMap 按 ipcMain 去重；两个 handle；set 成功广播；各窗口发送错误隔离 |
| ESM `createRemarksClient` | `api:{get,set,onChanged}` → `{subscribe,getSnapshot,load,save}` | 单连接共享快照、订阅计数、revision 和连接代号保护 |
| client.subscribe | `(listener:()=>void)` → `()=>void` | 首订阅连接并 load；最后退订清理；同一退订函数可安全调用两次 |
| client.getSnapshot | `()` → `{status,revision,projectRemarks,error}` | 无变化保持对象引用；error 为 null 或 Error，供 UI 状态判断 |
| client.load | `()` → `Promise<void>` | 重试读取；本地保存已成功时，迟到读取错误不覆盖其成功状态；load 不产生未处理拒绝 |
| client.save | `({key,remark})` → `Promise<void>` | api.set 成功才发布快照；失败抛给编辑框；迟到应答不得覆盖新 revision |
| ESM `renderProjectRemarkGroup` | `(props:{factoryProjectKey:string,label:string,tooltip?:string,contextMenuItems?:Array},ui:附录A2依赖对象)` → React element | 只替换 label/tooltip/menu；原生 Group 和原生 Modal 同级渲染 |
| 组件内部 openEditor/saveEditor/closeEditor | 无参数 → 更新组件状态，saveEditor 为 Promise<void> | 首次打开复制当前备注；保存中禁重复/关闭；取消不写；IME Enter 与卸载受保护 |

CJS 使用 `module.exports={createRemarksStore,registerProjectRemarks}`；ESM 使用具名 export，不 import React 或 Electron。preload 参数只含 key/remark，不能提交路径或整份 map；get/set 异常不经 unhandledRejection 外溢。模块内 UI 单例仅保存 client，禁止缓存某个项目的 props 或把全局编辑草稿共享给多个项目。

```js

test('广播先到时旧 get/set 应答不回退，退订后重连重新读取', async () => {
  const events = [], reads = [];
  let changed, resolveSave;
  const api = {
    onChanged: listener => {
      events.push('subscribe'); changed = listener;
      return () => { events.push('unsubscribe'); changed = null; };
    },
    get: () => { events.push('get'); return new Promise(r => reads.push(r)); },
    set: () => new Promise(r => { resolveSave = r; })
  };
  const client = createRemarksClient(api);
  const stop = client.subscribe(() => {});
  assert.deepEqual(events.slice(0, 2), ['subscribe', 'get']);

  assert.equal(client.getSnapshot().projectRemarks.x, '广播');
  const stable = client.getSnapshot();
  assert.equal(client.getSnapshot(), stable);
  const saving = client.save({ key: 'x', remark: '保存' });
  changed({ revision: 3, projectRemarks: { x: '更新的广播' } });
  resolveSave({ revision: 2, projectRemarks: { x: '保存' } });
  await saving;
  assert.equal(client.getSnapshot().revision, 3);
  stop(); stop();
  assert.equal(events.filter(e => e === 'unsubscribe').length, 1);
  const stopAgain = client.subscribe(() => {});
  assert.equal(reads.length, 2);
  reads[1]({ revision: 3, projectRemarks: { x: '更新的广播' } });
  await new Promise(setImmediate);
  stopAgain();
});
```
